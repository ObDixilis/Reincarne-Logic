# Star Weaver implementation contract

Baseline: user approved SW-SKILL-001 on October 22, 2026 in the originating chat and explicitly requested implementation and GitHub upload. Preserve Affinity and Techfinity independence and Finity Context Doubt. The earlier proposal is preserved in approved-baseline.md as historical evidence. New hereditary policy remains an explicit experimental rule set, not an asserted universal genetic law.

Deliver a local, dependency-free Python 3.10+ browser workbench in this module. It must perform real learning, activation, tick progression, interruption, refund, persistence, export/import, and lineage generation. Keep the five-node graph and its actual costs. Render outputs as identifiable light/signal/beacon effects. No external APIs or paid services at runtime. Bind to loopback only. Existing root web and iOS prototypes remain independent.

HTTP contract (JSON unless noted):

- GET /api/bootstrap => {graph, session, lineage_catalog, lineage_rules, decisions, version}. Session is {revision, state, nodes, last_lineage}; state matches baseline Model fields; nodes maps ID to {availability, reason, learnable, learn_reason, next_growth_cost}. Every response has Content-Type and no-store.
- POST /api/action accepts {revision, action, request_id, node?, ticks?, axis?, access?, equipped?, cascade?}. Actions: learn, activate, advance, set_axis, set_lamp, respec, restore_resources, reset. Successful mutation => {session, result}. Rejections return status 400 with {error}; stale revision returns 409 with {error, session}. Restore resources is explicitly a sandbox control. Reset starts the approved fixture, clearing lineage.
- POST /api/lineage accepts {parent_a, parent_b, seed}; preview-only response {lineage}. IDs select synthetic catalog profiles; seed is a bounded string. No save mutation.
- POST /api/apply-lineage accepts {revision, lineage, request_id}; server verifies/recomputes generation using parent IDs and seed rather than trusting derived fields. Starts an incarnation at all ranks zero, baseline growth/resources, no equipment, both axes unavailable. Inherited potential is recorded, never converted to active access or learned ranks. Response {session, result}.
- GET /api/export => {format: star-weaver-save, version: 1, session}; POST /api/import accepts {revision, save, request_id}; validate before atomic replacement. Enforce size/type/range/reference/digest checks. No arbitrary filesystem paths.
- GET /api/health => {status: ok, version}.

Frontend: vanilla HTML/CSS/JS, no framework/build dependency. Three clear areas/views: skill graph and node detail; lineage/cross-breed workbench and trace; source/decisions. Required IDs: node-M0, node-T0, node-A1, node-T1, node-H1 (selectable buttons); learn-node, activate-node, tick-forward, respec-node; axis-affinity, axis-techfinity selects; lamp-equipped checkbox; restore-resources; reset-session; export-save; import-save file input; parent-a, parent-b selects; lineage-seed input; generate-lineage; apply-lineage; export-lineage; lineage-result; status-message role=status. A node card selection updates the detail panel. Keep render and persistent state separate, handle 409 by refreshing session and requiring a fresh intended action, and never auto-retry a mutation. All inputs labeled; keyboard and 390px width supported; reduced-motion honored. Lineage preview controls disabled until loaded; errors do not erase the last good UI. Local SVG/CSS visual identity: Gorgon Void #030106 base, restrained Medusa Will #FF2BD6 for magical expression, Circuit Cyan #00E5FF technology, Solar Amber #FFB000 composed state. No stock assets required for a graph workbench.

Lineage module contract: starweaver/heredity.py exports load_catalog(data_dir: Path) -> dict and generate_lineage(catalog: dict, parent_a: str, parent_b: str, seed: str) -> dict. Catalog root {profiles: [{id,label,description,traits:[trait IDs]}], traits:[{id,label,channel,axis,description,...}], rules:{...}}. Deterministic, bounded, transparent inheritance with exact parent/trait provenance and experimental rule ID. Return {id, parent_ids:[...], seed, ruleset_id, status:'EXPERIMENTAL', traits:[...], axis_potential:{Affinity:bool,Techfinity:bool}, learned_skills:[], active_axis_access:{Affinity:'unavailable',Techfinity:'unavailable'}, branches:[...], trace:[...]}. Return no installed equipment or learned nodes. At least six synthetic profiles and trait routes covering biological, resonant, cultural/mentorship, fabricated/blueprint routes; zero/one/two-axis potential combinations; stable seed behavior; exclude Finity. Distinguish hereditary potential from teaching and fabricated succession explicitly; all are provenance routes, not all biological crossbreeding. Include readable pathway diagrams and at least one multi-generation example using explicit generation outputs or a documented composition process. No real people or invented canonical species/bloodlines.

Acceptance: preserve approved 25 behavior checks; add meaningful lineage, API, persistence, invalid-save and transaction tests; run actual browser journeys for learn/use/interruption/resume and lineage preview/apply/export at desktop and mobile widths.
